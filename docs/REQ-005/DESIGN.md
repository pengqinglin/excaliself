# REQ-005 技术方案

使用 Codex CLI 的 exec --json 与 Streamable HTTP MCP 配置，复用成员已有 Codex 登录和模型配置。以 argv 数组启动，不调用 shell；令牌只通过 EXCALISELF_TOKEN 环境变量传给 MCP，禁用普通创建/提案工具，模型仅使用任务场景读取、提交和回执查询。CLI 工作目录与连接器状态隔离。

连接器维护 0700 状态目录、0600 原子状态文件和进程锁。持久 worker UUID、每会话 Codex thread ID 与尚未确认的最终回报；不写令牌。重新启动先重报未确认结果，再发现任务。会话恢复使用 thread ID 和数据库完整消息/既有操作上下文；新控制版本强制重新读取。

任务执行与控制监视独立：每 2 秒读取控制，每 15 秒续租；暂停、新消息、失去租约、凭据撤销或退出立即中断子进程，5 秒未退出强杀。实际停止后才确认暂停；恢复重新确认消息并启动新的 fenced 执行。任务状态及提交仍由服务端校验，进程中断不是唯一屏障。

MCP 客户端初始化并支持 JSON/SSE 响应，单请求超时和指数退避。最终结果先写本地 journal，再带固定 requestId 上报；未知响应重试相同内容。关闭终端仍需 systemd/容器等持续运行，随 REQ-009 提供示例。
