# 历史犯错与防复发记录

最后更新：2026-11-25

仅记录实际发生且影响实施或验证的错误。每项包含发生任务、事实、根因、修复、验证和防复发措施；潜在问题记录在对应需求的技术方案。

## 记录

### M001：开发工具安装参数与数据库创建权限

- 日期 / 任务：2026-11-25，REQ-001 环境准备。
- 事实：npm 阻止 Node 包安装脚本；尝试用项目安装不支持的 `--allow-scripts` 参数重建失败。随后普通数据库角色创建测试数据库因无 CREATEDB 权限失败。
- 根因：未先核对 npm 新版的项目级脚本许可方式；误将数据库所有者权限与创建数据库权限混同。
- 修复：只在工作区隔离工具的 package.json 中允许 node 安装脚本；由 PostgreSQL 管理员创建专用数据库并指定 user 为所有者。
- 验证：隔离 Node 22.23.5、pnpm 11.14.0 已可运行；PostgreSQL 17.12 的专用数据库连接成功。
- 防复发：记录项目级安装脚本许可和最小数据库权限，测试只连接独立测试库。

### M002：复合外键的被引用唯一键创建顺序

- 日期 / 任务：2026-11-25，REQ-001-T02。
- 事实：首次迁移测试失败，Drizzle 生成器把 runs 的复合唯一索引排在引用它的外键之后。
- 根因：被复合外键引用的唯一性使用独立索引声明，生成时尚未存在。
- 修复：改成表内 UNIQUE 约束，重新生成尚未交付的迁移及元数据。
- 验证：重新执行完整迁移、约束与旧库升级测试，结果见 REQ-001/VALIDATION。
- 防复发：被复合外键引用的键优先使用表内约束；迁移必须实际运行，不能只看生成成功。

### M003：并行检查竞争生成的国际化代码

- 日期 / 任务：2026-11-25，REQ-001-T04 验证。
- 事实：并行运行 Vitest 和 typecheck 时，已有界面出现 ParaglideMessage 的 inputs 类型错误；两者结束后顺序运行 typecheck 通过。
- 根因：两项命令都会重新生成 `src/paraglide`，TypeScript 在竞争期间读到了临时生成状态。
- 修复：Vitest 和 typecheck 顺序执行，其他无共享生成输出的检查仍可独立运行。
- 验证：顺序类型检查通过，未修改无关的界面代码。
- 防复发：把共享代码生成目录视为检查依赖，禁止并行执行这些生成步骤。

### M004：Room 串行队列的生命周期顺序

- 日期 / 任务：2026-11-25，REQ-003-T01。
- 事实：初版队列使重连等待一个尚未结束的 flush，造成两个已有测试超时；terminate 在排队笔画前清座位造成最后一笔未保存。
- 根因：把只读初始场景也排进写入队列，且座位清理没有保持与已排队修改的顺序。
- 修复：初始场景可读取最后已提交的内存快照，提交后再收广播；终止清理排在已收到修改之后，已移除座位的帧立即拒绝。
- 验证：103 项 Room 回归和 7 项后台提交测试全部通过。
- 防复发：生命周期修改必须跑最后一笔、shutdown、写入期间重连等既有测试；迁移生成也必须显式传入隔离测试库的 DATABASE_URL。

### M005：面板空任务的可选链比较

- 日期 / 任务：2026-11-25，REQ-006-T03。
- 事实：回执界面测试中的消息 fixture 未提供 runId，`latest?.id === message.runId` 两侧均为 undefined，进入了需要任务对象的分支并崩溃。
- 根因：只用可选链比较结果作为对象存在的前提，依赖了消息始终完整的假设。
- 修复：显式检查 latest 存在，再比较任务 ID；保留无任务回执与纯文本渲染验证。
- 验证：面板、分页和交接 18 项通过；后续撤回界面测试也通过。
- 防复发：条件分支先检查必需对象存在，不能把两个可选字段相等视为对象存在证明。

### M006：更换凭据后无法恢复已保存的最终回报

- 日期 / 任务：2026-11-25，REQ-010-T02 恢复审查。
- 事实：服务端已提交最终回报、连接器未收到响应时，更换同成员个人令牌再重放 journal 会返回 `idempotency_conflict`。
- 根因：回报请求哈希包含凭据 ID；新令牌改变哈希，即使成员、原执行实例、任务、代次及回报正文均相同。
- 修复：最终回报去重哈希绑定成员、原 workerId 和完整回报输入。重放先验证当前凭据及私人会话；任何未保存的新回报仍必须通过原凭据绑定的有效租约检查。场景提交的凭据屏障保持原语义。
- 验证：新增真实 MCP handler/PGlite 回归先复现失败，再验证换令牌恢复已保存回复、journal 清空且模型不再执行；相关 24 项任务/连接器测试通过。
- 防复发：恢复测试覆盖同成员换凭据与换成员两种不同情形，不能仅验证同令牌跨进程恢复。

### M007：后台新增元素在浏览器补索引时使撤回过期

- 日期 / 任务：2026-11-25，REQ-010-T02 真实浏览器联调。
- 事实：后台新增带标签形状后，重新打开绘图立即点击撤回却报告冲突；数据库比对显示形状和标签仅被补了 index，但 version/nonce 已增加。
- 根因：复用供浏览器 Apply 使用的 planner，新增元素 index 为 null；Excalidraw 在打开时自动生成索引并推进版本，回执中的 after 版本因此失效。
- 修复：服务端后台提交在持久化前用独立 `fractional-indexing` 包为新增元素分配当前场景之后的合法索引，原场景元素保持其索引；回执、数据库和广播使用同一份结果。独立导入避免服务端加载依赖 DOM 的 Excalidraw 包。
- 验证：新增带现有人工作品的形状/标签索引与回执一致性回归；场景、撤回、任务和连接器 4 文件 38 项通过，最终全量 1501 项通过；真实浏览器关闭页面后完成、重开立即撤回成功且保留人工元素（REQ-010）。
- 防复发：端到端必须验证后台新增后重新打开并立即撤回，不能仅在原始 JSON 元素上验证版本屏障。
