# 全局项目任务规划

最后更新：2026-11-25

## 目标与已确定的边界

在已有 Excalidraw 画布上接入 AI 协作：成员从网页发送消息、暂停和继续任务，查看接收、处理、改图保存和最终结果。首个执行端为 Codex，经 MCP 连接；浏览器关闭后继续执行；对话与控制仅属于发起成员，实际画布修改按绘图原有权限同步。

Codex 连接器必须持续运行。MCP 连接本身不启动推理。现有部署仍按一个应用进程维护 Room；持久化任务不会自动带来多副本协作能力。

## 执行规则

1. 按顺序实施需求；开始时创建 `docs/REQ-NNN/`。
2. 每个需求包含 README、DESIGN、TODO、VALIDATION；每个子任务在 `tasks/` 有独立方案。
3. 状态为待执行、进行中、阻塞、已完成。同一时间只推进一个主子任务。
4. 先记录方案和验收标准，再写代码；验证完成后回填证据并关闭子任务。
5. 真实错误记入 [MISTAKES.md](MISTAKES.md)；风险与待确认设计写入需求方案。
6. 使用者可见的功能、配置和部署变化，同步更新用户文档与国际化；不把未交付功能描述为已可用。

## 跨需求技术约束

- 未启用助手的私人画布使用浏览器自动保存；团队、分享或已启用 server-managed 的画布由 Room 保存。助手首次发送前原子交接写入权。
- 普通 `edit_drawing` 的逐次提案机制遵循 ADR 0003；网页任务授权下的后台直接提交遵循 ADR 0004。
- 消息保存、执行端接收、处理、场景持久化和任务完成分别记录；最终自然语言回复不构成场景保存证明。
- 暂停与补充指令推进控制版本；旧执行结果、旧租约和重复提交不能产生新修改。
- 服务端 AI 修改是远端更新；撤回应通过带冲突检查的逆向操作实现。

## 全体验收

可在已有绘图上和 Codex 对话并协作；人机同时编辑不覆盖无关内容；暂停阻止迟到提交；关闭网页仍可完成；重试不重复改图；对话权限隔离；重启和断线可恢复；结果可追溯且可按约束撤回。
